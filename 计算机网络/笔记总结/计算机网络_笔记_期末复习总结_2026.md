# 计算机网络知识点总结

## 第 1 章 概述

### 1.1 计算机网络在信息时代中的作用

- **“三网融合”**：电信网络（电话、电报、传真）、有线电视网络（电视节目）、计算机网络（传送数据文件）三大网络逐步融合，核心是融入现代计算机网络技术。
- **Internet 译名与辨析**：互联网是目前流行最广的事实标准译名（“因特网”为推荐译名但未广泛推广）。注意：**互联网（Internet，大写 I）$\neq$ 互连网（internet，小写 i）**。
- **互联网的两个重要基本特点**：
  1. **连通性（Connectivity）**：使上网用户之间不管距离多远都可以非常便捷地交换各种信息，好像这些用户终端都彼此直接连通一样。
  2. **共享（Sharing）**：即资源共享，包括信息共享、软件共享和硬件共享。
- **“互联网+”**：指“互联网 + 各个传统行业”，把互联网的创新成果深度融合于经济社会各领域之中。

### 1.2 互联网概述

- **网络（network）**：由若干结点（node）和连接这些结点的链路（link）组成。结点可以是计算机、集线器、交换机或路由器等。
- **互连网（internetwork / internet，小写 i）**：多个网络通过路由器（router）相互连接起来，构成覆盖范围更大的计算机网络，即“网络的网络”。与网络相连的计算机常称为主机（host）。
- **互联网（Internet，大写 I）**：全球最大的、开放的、由众多网络相互连接而成的特定互连网，采用 TCP/IP 协议族作为通信规则（前身是美国的 ARPANET）。
- **互联网基础结构发展的三个阶段**：
  1. **第一阶段（1969–1990）**：从单个分组交换网 ARPANET 向互连网发展；**1983 年** TCP/IP 协议成为 ARPANET 上的标准协议（通常作为互联网诞生时间），1990 年 ARPANET 关闭。
  2. **第二阶段（1985–1993）**：建成三级结构的互联网——国家科学基金网 NSFNET（主干网、地区网、校园网/企业网）。
  3. **第三阶段（1993 年至今）**：形成多层次 ISP（互联网服务提供者）结构的互联网（按覆盖面积与拥有 IP 数目分为主干 ISP、地区 ISP、本地 ISP）。出现互联网交换点 **IXP**（允许两个网络直接相连并快速交换分组，常采用数据链路层交换机，较大 IXP 峰值吞吐量在 Tbit/s 量级）；**内容提供者（Content Provider）**向用户提供视频等内容而不提供转接服务；20 世纪 90 年代由欧洲核子研究组织 CERN 开发出万维网 WWW。
- **互联网的标准化工作**：
  - **管理机构**：互联网协会 **ISOC** 下设互联网体系结构研究委员会 **IAB**，下分互联网工程部 **IETF**（设互联网工程指导小组 IESG 及工作组 WG，负责短期工程技术标准）与互联网研究部 **IRTF**（设互联网研究指导小组 IRSG 及研究组 RG，负责长期研究课题）。
  - **RFC（Request For Comments，请求评论）**：全部可免费下载，按发表时间顺序编号 `RFCxxxx`，并非所有 RFC 都是互联网标准。
    - 标准轨道（第 8 版依据 RFC 6410 合并为 3 个阶段）：**互联网草案（Internet Draft）**（有效期 6 个月，非正式 RFC）$\to$ **建议标准（Proposed Standard）** $\to$ **互联网标准（Internet Standard，分配 STDxx 编号）**。
    - 非标准轨道：历史（Historic）、信息（Informational）、实验（Experimental）。

### 1.3 互联网的组成

互联网从工作方式上划分为**边缘部分**和**核心部分**。

#### 1. 边缘部分
由所有连接在互联网上的主机（又称端系统 end system）组成。“计算机之间通信”实质上是指：**主机 A 上的某个进程和主机 B 上的另一个进程进行通信**。端系统进程通信的两种方式：
- **客户-服务器方式（C/S 方式）**：描述进程之间服务与被服务的关系。通信关系建立后，通信可以是双向的，双方都可发送和接收数据。
  - **客户程序**：被用户调用后运行，主动向远地服务器发起通信（请求服务），必须知道服务器程序的地址，不需要特殊硬件和复杂操作系统。
  - **服务器程序**：专门用来提供某种服务，可同时处理多个远地或本地客户的请求；系统启动后一直不断运行，被动等待并接受来自各地客户的请求，无需知道客户程序的地址，一般需要强大的硬件和高级操作系统支持。
- **对等连接方式（P2P 方式）**：两台主机在通信时不区分服务请求方和服务提供方，只要运行 P2P 软件即可进行平等的、对等连接通信（本质上仍是 C/S 方式，只是每台主机既是客户又是服务器）。

#### 2. 核心部分
由大量网络和连接这些网络的路由器（router）组成，向网络边缘中的主机提供连通性。核心部分最关键的技术是**交换（switching）**——按某种方式动态地分配传输线路的资源。路由器处理分组的 4 个步骤：**暂存收到的分组 $\to$ 检查分组首部 $\to$ 查找转发表 $\to$ 按目的地址从合适接口转发出去**。

| 交换方式 | 工作原理 | 主要优点 | 主要缺点 |
| :--- | :--- | :--- | :--- |
| **电路交换** | 建立连接 $\to$ 通话（占用专用物理通路） $\to$ 释放连接 | 通信时延小；有序传输；没有冲突；实时性强 | 建立连接时间长；信道利用率极低（传突发数据时常 $<10\%$ 甚至 $<1\%$）；灵活性差；$N$ 部电话两两直连需 $N(N-1)/2$ 对电线 |
| **报文交换** | 基于存储转发，整个报文作为整体逐跳转发 | 无需建立连接；动态分配线路，信道利用率高 | 转发时延较长（几分钟到几小时）；对中间结点缓存要求高 |
| **分组交换** | 将报文划分为固定上限长度的分组（包），加上首部后独立选路、存储转发 | **高效**（动态分配带宽、逐段占用链路）；**灵活**（独立选路）；**迅速**（无需建连）；**可靠**（网络协议与分布式多路由生存性） | 分组在各路由器存储转发时存在排队时延；不保证带宽；首部、暂存分组与维护转发表带来额外开销 |

- **连续大量数据与突发数据对比**：若连续传送大量数据且传送时间远大于连接建立时间，电路交换传输速率较快；传送突发数据时，报文交换和分组交换信道利用率高，且分组交换因分组长度远小于报文而时延更小。

### 1.4 计算机网络在我国的发展

- 1989 年 11 月，我国第一个公用分组交换网 **CNPAC** 建成运行；**1994 年 4 月 20 日**我国通过 64 kbit/s 专线正式接入互联网；1994 年 5 月中科院高能物理所设立国内首个 WWW 服务器。
- 1994 年启动建设我国第一个 IPv4 互联网主干网 **CERNET**（2004 年 2 月开通下一代互联网主干网 **CERNET2**，以 2.5–10 Gbit/s 连接北京、上海、广州）。我国五大公用计算机网络：**CHINANET、UNINET、CMNET、CERNET、CSTNET**。中国互联网络信息中心（**CNNIC**）每年两次发布互联网发展状况报告。

### 1.5 计算机网络的类别

- **计算机网络较好定义**：主要是由一些通用的、可编程的硬件（一定包含 CPU）互连而成的，这些可编程硬件能够用来传送多种不同类型的数据，并能支持广泛的和日益增长的应用。
- **按作用范围分类**：
  - **广域网 WAN**（又称远程网）：作用范围通常为几十到几千公里（互联网的核心部分）。
  - **城域网 MAN**：作用范围一般为一个城市，约 5–50 km。
  - **局域网 LAN**：局限在较小的范围（如 1 km 左右，校园网或企业网）。
  - **个人区域网 PAN**：个人工作场所范围，约 10 m 左右（WPAN）。
- **按使用者分类**：**公用网（公众网）**（按规定交费即可使用）与**专用网**（特定部门专用，如军队、铁路、银行）。
- **接入网 AN（Access Network）**：又称本地接入网或居民接入网，属于本地 ISP 拥有的网络，用于将用户端系统接入互联网（既不属于核心部分，也不属于边缘部分，是从用户端系统到本地 ISP 第一个路由器/边缘路由器之间的网络；从覆盖范围看许多接入网仍属于局域网）。

### 1.6 计算机网络的性能

#### 1. 性能指标
1. **速率（Speed / Data Rate）**：数据传送速率（比特率），单位 `bit/s`（`b/s` 或 `bps`），通常指额定/标称速率而非实际运行速率。**网络速率换算采用十进制**（$k=10^3, M=10^6, G=10^9, T=10^{12}$），**存储容量通常采用二进制**（$1\text{ KB}=2^{10}\text{ B}=1024\text{ B}$，$1\text{ MB}=2^{20}\text{ B}$）。
2. **带宽（Bandwidth）**：在计算机网络中表示某通道所能传送数据的能力，即单位时间内某信道所能通过的最高数据率（单位 `bit/s`）；原频域含义为信号具有的频带宽度（单位 `Hz`）。
3. **吞吐量（Throughput）**：单位时间内通过某个网络（或信道、接口）的实际数据量，受网络带宽或额定速率限制（额定速率为绝对上限，实际吞吐量可能远小于额定速率甚至下降到 0；有时也用每秒字节数或帧数表示）。
4. **时延（Delay / Latency）**：数据从网络一端传送到另一端所需的总时间，由 4 部分组成：
   - **发送时延（传输时延）**：主机或路由器发送数据帧所需的时间，$t_s = \frac{\text{数据帧长度 (bit)}}{\text{发送速率 (bit/s)}}$。发生在机器内部的发送器中，与信道长度无关。
   - **传播时延**：电磁波在信道中传播一定距离花费的时间，$t_p = \frac{\text{信道长度 (m)}}{\text{电磁波传播速率 (m/s)}}$。自由空间光速 $3.0\times 10^8\text{ m/s}$，铜线约 $2.3\times 10^8\text{ m/s}$，光纤约 $2.0\times 10^8\text{ m/s}$。
   - **处理时延**：主机或路由器分析首部、提取数据、差错检验或查找路由所花的时间。
   - **排队时延**：分组在输入/输出队列中等待处理或转发的时间（通信量过大导致队列溢出丢包时相当于排队时延为无穷大）。
   - **总时延** $= t_s + t_p + t_{\text{处理}} + t_{\text{排队}}$。
5. **时延带宽积**：$\text{时延带宽积} = \text{传播时延 } t_p \times \text{带宽}$，表示按比特计数的链路长度（即链路上正在传播、尚未到达终点的比特数）。只有管道充满比特时链路才得到充分利用。
6. **往返时间 RTT（Round-Trip Time）**：从发送方发送完数据到收到接收方确认为止总共经历的时间（包括双向传播时延及中间结点的处理、排队、转发时延；卫星通信中 RTT 较长）。$\text{有效数据率} = \frac{\text{数据长度}}{\text{发送时间 } t_s + \text{RTT}}$。
7. **利用率**：分为信道利用率（某信道有百分之几的时间被利用）和网络利用率（全网信道利用率的加权平均值）。根据排队论：
   $$D = \frac{D_0}{1 - U}$$
   其中 $D_0$ 为网络空闲时的时延，$D$ 为当前时延，$U$ 为网络利用率（$0 \le U < 1$）。当 $U \to 1$ 时时延急剧增大，因此信道利用率并非越高越好（通常保持在 50% 以下）。

#### 2. 非性能特征
包括费用、质量、标准化、可靠性、可扩展性和可升级性、易于管理和维护。

### 1.7 计算机网络体系结构

- **形成与发展**：ARPANET 提出分层设计；IBM 提出 SNA；ISO 制定七层 **OSI/RM（ISO 7498，法律上的国际标准）**。OSI 因缺乏商业驱动力、协议过分复杂且运行效率低、制定周期过长、层次划分不合理（部分功能在多层重复）而未能成为主流，**TCP/IP 成为事实上的国际标准**。
- **网络协议三要素**：
  1. **语法**：数据与控制信息的结构或格式。
  2. **语义**：需要发出何种控制信息、完成何种动作以及做出何种响应。
  3. **同步（时序）**：事件实现顺序的详细说明。
- **协议的两种形式**：文字描述（便于人阅读）与程序代码（使计算机能够执行）。
- **两军问题**：蓝军与白军博弈表明，在不可靠信道上没有一种协议能保证 100% 一致行动，说明协议设计必须周密应对各种异常和丢包。
- **分层的优缺点与主要功能**：
  - **优点**：（1）各层之间相互独立；（2）灵活性好；（3）结构上可分割开；（4）易于实现和维护；（5）能促进标准化工作。
  - **缺点**：有些功能会在不同层次中重复出现，产生额外开销。
  - **各层完成的主要功能**：差错控制、流量控制、分段和重装、复用和分用、连接建立和释放。
- **体系结构与实现**：体系结构（Architecture）是计算机网络各层及其协议的集合（抽象定义，不涉及实现）；实现（Implementation）是遵循体系结构前提下用硬件或软件完成功能（具体工程）。
- **三种体系结构对照**：
  - **OSI 七层**：物理层(1)、数据链路层(2)、网络层(3)、运输层(4)、会话层(5)、表示层(6)、应用层(7)。
  - **TCP/IP 四层**：网络接口层(1)、网际层 IP(2)、运输层 TCP/UDP(3)、应用层(4)。路由器在转发分组时最高只用到网际层，不使用运输层和应用层；部分应用可直接使用 IP 层或网络接口层。
  - **五层协议体系结构**（教学原理模型）：

| 层次 | 协议数据单元（PDU） | 封装说明 | 核心功能 | 典型协议 / 设备 |
| :--- | :--- | :--- | :--- | :--- |
| **5 应用层** | 报文（Message） | 加首部 H5 | 通过应用进程间交互完成特定网络应用 | HTTP、DNS、FTP、SMTP、DHCP |
| **4 运输层** | 报文段（TCP）/ 用户数据报（UDP） | 加首部 H4 | 负责向两台主机中进程之间的通信提供通用的数据传输服务（复用与分用） | TCP、UDP |
| **3 网络层** | 分组 / IP 数据报（Packet） | 加首部 H3 | 为分组交换网上的不同主机提供通信服务；路由选择与分组转发 | IP、ARP、ICMP、RIP、OSPF、BGP；路由器 |
| **2 数据链路层** | 帧（Frame） | 加首部 H2 与尾部 T2 | 在两个相邻结点间的链路上将 IP 数据报组装成帧，透明传输与差错检测（默认丢弃出错帧） | PPP、Ethernet（CSMA/CD）；网桥、交换机 |
| **1 物理层** | 比特（Bit） | 转为电/光信号 | 透明地传送比特流（确定接口的机械、电气、功能、过程特性；媒体在物理层之下为第 0 层） | 转发器、集线器 |

- **实体、协议、服务与服务访问点（SAP）**：
  - **实体（Entity）**：任何可发送或接收信息的硬件或软件进程。
  - **协议**：**水平的**，控制两个对等实体进行通信的规则集合；协议的实现保证了能够向上一层提供服务，本层服务用户只能看见服务而看不见下面的协议。
  - **服务（Service）**：**垂直的**，由下层向上层通过层间接口提供的功能。
  - **服务访问点（SAP）与服务原语**：同一系统中相邻两层实体进行交互的逻辑接口，通过 SAP 交换**服务原语**；层间交换的数据单位为**服务数据单元（SDU）**（多个 SDU 可合装为一个 PDU，一个 SDU 也可划分为几个 PDU）。
- **TCP/IP 沙漏型体系结构**：体现 `Everything over IP`（IP 层支持多种运输层与应用层协议）和 `IP over Everything`（IP 协议可在多种异构网络上运行），设计理念为“网络核心部分越简单越好”。

## 第 2 章 物理层

### 2.1 物理层的基本概念

物理层考虑的是怎样才能在连接各种计算机的传输媒体上传输数据比特流，而不是指具体的传输媒体。物理层的主要作用是尽可能屏蔽传输媒体和通信手段的差异。物理层协议（规程）用于确定与传输媒体接口的四大特性：
1. **机械特性**：指明接口所用接线器的形状和尺寸、引线数目和排列、固定和锁定装置等。
2. **电气特性**：指明在接口电缆的各条线上出现的电压的范围。
3. **功能特性**：指明某条线上出现的某一电平的电压的意义。
4. **过程特性**：指明对于不同功能的各种可能事件的出现顺序。

### 2.2 数据通信的基础知识

#### 1. 数据通信系统模型与常用术语
- **三大部分**：源系统（信源 + 发送器，如 PC + 调制器）、传输系统（传输网络）、目的系统（接收器 + 信宿）。
- **常用术语**：
  - **消息（Message）**：话音、文字、图像、视频等。
  - **数据（Data）**：运送消息的实体，有意义的符号序列。
  - **信号（Signal）**：数据的电气或电磁表现。模拟信号（连续信号）参数取值连续；数字信号（离散信号）参数取值离散。
  - **码元（Symbol）**：在使用时间域的波形表示数字信号时，代表不同离散数值的基本波形（$M$ 进制码元携带 $\log_2 M$ 比特信息）。

#### 2. 信道与通信交互方式
信道一般表示向某一个方向传送信息的媒体，一条通信电路往往包含发送信道和接收信道。
- **单向通信（单工）**：只能有一个方向的通信，没有反方向交互（如无线电广播、电视广播）。
- **双向交替通信（半双工）**：通信双方都可以发送信息，但不能同时发送或接收（如对讲机）。
- **双向同时通信（全双工）**：通信双方可以同时发送和接收信息，传输效率最高。

#### 3. 基带信号与编码/调制
来自信源的信号称为基带信号，包含较多低频和直流成分：
- **基带调制（编码）**：仅对基带信号波形进行变换，把数字信号转换为另一种形式的数字信号。
- **带通调制**：使用载波将基带信号的频率范围搬移到较高频段并转换为模拟信号（称为带通信号）。
- **数字信号常用编码方式**：
  - **不归零制（NRZ）**：正电平代表 1，负电平代表 0（无自同步能力，长串 0/1 时时钟易失步）。
  - **归零制（RZ）**：正脉冲代表 1，负脉冲代表 0，一个码元内必回到零电平。
  - **曼彻斯特编码（Manchester）**：位周期中心的向上跳变代表 0，向下跳变代表 1（也可反过来定义）。每个码元中间都有跳变，具有自同步能力，但所占频带宽度比不归零制高一倍（传统以太网采用）。
  - **差分曼彻斯特编码**：位周期中心始终有跳变提供时钟同步；若位周期开始边界有跳变代表 0，没有跳变代表 1（抗干扰能力更强，用于令牌环网）。

- **基本带通调制方法**：
  - **调幅（AM / ASK）**：载波的振幅随基带数字信号而变化。
  - **调频（FM / FSK）**：载波的频率随基带数字信号而变化。
  - **调相（PM / PSK）**：载波的初始相位随基带数字信号而变化。
  - **正交振幅调制（QAM）**：将振幅和相位结合起来的多元制混合调制（例如 12 种相位结合 1 或 2 种振幅构成 16 种组合即 `16-QAM`，每个码元携带 $\log_2 16 = 4$ 比特信息，数据率提高 4 倍）。

#### 4. 信道的极限容量
- **波形失真加重的四个因素**：码元传输速率越高、传输距离越远、噪声干扰越大、传输媒体质量越差。
- **码间串扰**：高频分量无法通过受限带宽的信道，导致接收端信号波形失去码元之间的清晰界限。
- **奈氏准则（理想低通信道，无噪声）**：在任何信道中，码元传输速率是有上限的，超过此上限会出现严重码间串扰。
  - 极限码元速率：$B_{\max} = 2W$ 波特（$W$ 为理想低通信道带宽，单位 Hz；波特 = 码元/秒）。
  - 若每个码元有 $M$ 种离散状态，则极限信息传输速率：
    $$C = 2W \log_2 M \text{ (bit/s)}$$
  - 工程意义：激励工程人员探索先进编码技术，让每一个码元携带更多比特信息量。
- **香农公式（受随机高斯热噪声干扰的信道）**：
  $$C = W \log_2\!\left(1 + \frac{S}{N}\right) \text{ (bit/s)}$$
  其中 $W$ 为信道带宽（Hz），$S$ 为信号平均功率，$N$ 为信道内部高斯噪声平均功率。信噪比常用分贝（dB）度量：
  $$\text{SNR (dB)} = 10 \log_{10}\!\left(\frac{S}{N}\right)$$
  （如 $S/N = 10 \Rightarrow 10\text{ dB}$；$S/N = 1000 \Rightarrow 30\text{ dB}$）。
  - 物理与工程意义：在实际有噪声的信道上，不论采用多复杂的编码技术，都不可能突破香农公式给出的绝对极限；并且**只要信息传输速率低于信道的极限信息传输速率，就一定可以找到某种办法来实现无差错的传输**。

### 2.3 物理层下面的传输媒体

#### 1. 导引型传输媒体
- **双绞线**：两根互相绝缘的铜导线按规则绞合（绞合度越高可用数据率越高；各类双绞线衰减均随频率升高而增大，最高速率还与数字信号编码方法有关）。
  - **无屏蔽双绞线 UTP**：无屏蔽层，价格便宜。
  - **屏蔽双绞线 STP**：外加金属屏蔽层并必须接地。命名规则：`F` 为铝箔、`S` 为金属编织层、`SF` 为铝箔外加金属编织层、`U` 为无屏蔽；斜杠前指电缆总屏蔽，斜杠后指每对线屏蔽。常见抗干扰能力排序：`SF/FTP > S/FTP > F/FTP > U/FTP > F/UTP > UTP`。
  - **EIA/TIA-568 双绞线标准**：

| 类别 | 带宽 | 典型应用 |
| :--- | :--- | :--- |
| **3 类（Cat 3）** | 16 MHz | 模拟电话、传统以太网（10 Mbit/s，2 对 4 芯） |
| **5 类（Cat 5）** | 100 MHz | 100 Mbit/s（100BASE-TX，距离 100 m） |
| **超 5 类（Cat 5e）** | 125 MHz | 1 Gbit/s（1000BASE-T，距离 100 m） |
| **6 类（Cat 6）** | 250 MHz | 10 Gbit/s（距离 35–55 m，可使用屏蔽） |
| **6A 类（Cat 6A）** | 500 MHz | 10 Gbit/s（距离 100 m，可使用屏蔽） |
| **7 类（Cat 7）** | 600 MHz | 超过 10 Gbit/s（必须屏蔽，100 m） |
| **8 类（Cat 8）** | 2000 MHz | 25 Gbit/s 或 40 Gbit/s（必须屏蔽，30 m） |

- **同轴电缆**：内导体铜质芯线 + 绝缘层 + 网状编织外导体屏蔽层 + 塑料外层，抗干扰性好（$50\ \Omega$ 用于基带数字传输，$75\ \Omega$ 用于有线电视宽带传输）。
- **光缆（光纤）**：发送端采用光源（发光二极管 LED 或半导体激光器 LD）产生光脉冲，接收端采用光检测器（光电二极管）还原电脉冲，利用高折射率纤芯与低折射率包层的**全反射**原理传播；光缆由数十至数百根光纤、加强芯与填充物、（必要时）远供电源线及护套构成。
  - **多模光纤**：纤芯较粗，允许多条不同角度入射的光线同时传输，会产生色散展宽失真，适用于近距离传输（可用较便宜的 LED）。
  - **单模光纤**：纤芯直径减小到只有一个光波长（几个微米），只允许一条光线直线传播，衰耗小，适合远距离、高速通信（必须使用昂贵的半导体激光器 LD）。
  - **三个常用光波段中心**：850 nm（损耗较大）、1300 nm、1550 nm（损耗最小），带宽均达 25000–30000 GHz。
  - **光纤优点**：通信容量非常大；传输损耗小、中继距离长；抗雷电和电磁干扰性能好；无串音干扰、保密性好；体积小、重量轻。

#### 2. 非导引型传输媒体
无线电波在自由空间传播，频段范围为 LF 至 THF（30 kHz–3000 GHz）。
- **无线信道误码率影响规律**：给定调制方式和数据率时，信噪比越大误码率越低；相同信噪比下，数据率越高的调制技术误码率越高；用户改变地理位置会导致信道特性、信噪比和误码率变化。
- **微波通信**：频率 300 MHz–300 GHz（波长 1 m–1 mm），主要使用 2–40 GHz，沿直线视距（LOS）传播。
  - **多径效应**：信号经障碍物多次反射沿多条路径按不同时间到达接收方，叠加产生失真。
  - **微波接力**：地球表面传播距离受限（约 50 km，100 m 高天线塔可达 100 km），需设中继站放大转发。优点：频段宽容量大、受工业与天电干扰小、投资少见效快；缺点：须视距传播且有多径效应、易受恶劣气候影响、保密性差、中继站维护耗费人力物力。
  - **卫星通信**：同步地球卫星覆盖跨度达 18000 多公里，容量大、距离远、费用与距离无关，但**单程传播时延较大（250–300 ms）**、保密性较差、造价较高（注意：传播时延大并不等于传送数据的总时延一定大）；低轨道（LEO）卫星高度在 2000 km 以下。
- **ISM 频段**：无需申请无线电频谱许可证即可自由使用的频段，主要包括 `902–928 MHz`、`2.4–2.4835 GHz`、`5.725–5.850 GHz`。

### 2.4 信道复用技术

复用允许多个用户使用一个共享信道进行通信（成对使用复用器和分用器）。
- **频分复用（FDM）**：所有用户在同样的时间占用不同的带宽（频带）资源。对应多址接入为 FDMA。
- **时分复用（TDM，等时信号）**：所有用户在不同的时间占用同样的频带宽度，每个用户在每个 TDM 帧中占用固定序号的时隙（周期性出现）。缺点：用户无数据发送时时隙空闲，信道利用率不高。对应多址接入为 TDMA。
- **统计时分复用（STDM，异步时分复用）**：按需动态分配时隙，集中器将各用户的数据加上控制/地址标记后放入 STDM 帧中发送，显著提高信道利用率。
- **波分复用（WDM / DWDM）**：光的频分复用，在一根光纤上同时传输多个不同波长的光载波信号（如 8 路 2.5 Gbit/s 载波 1550–1557 nm 复用为 20 Gbit/s，每隔约 120 km 放置一个**掺铒光纤放大器 EDFA** 直接放大光信号）。
- **码分复用（CDM）/ 码分多址（CDMA）**：每个用户可以在同样的时间使用同样的频带进行通信，各用户使用互相正交的 $m$ 位码片（chip）序列（扩频分为直接序列扩频 DSSS 与跳频扩频 FHSS）：
  - 若信息数据率为 $b\text{ bit/s}$，实际发送码片速率为 $mb\text{ bit/s}$，占用频带宽度提高到 $m$ 倍。
  - 发送比特 1：发送自己的 $m\text{ bit}$ 码片序列；发送比特 0：发送该码片序列的二进制反码（$+1$ 表示 1，$-1$ 表示 0，未发送为 0）。
  - 规格化内积：$\mathbf{S}\cdot\mathbf{T} = \frac{1}{m}\sum_{i=1}^m S_i T_i = 0$（不同站正交）；$\mathbf{S}\cdot\mathbf{S} = +1$；$\mathbf{S}\cdot(-\mathbf{S}) = -1$。

### 2.5 数字传输系统

- **早期 PCM 速率体系的两大缺点**：（1）速率标准不统一（北美和日本 `T1 = 1.544 Mbit/s`，欧洲及我国 `E1 = 2.048 Mbit/s`）；（2）采用**准同步方式**，各支路时钟存在频率偏差，导致时分复用和分用困难。
- **同步光纤网 SONET 与同步数字系列 SDH**：各级时钟来自同一精确主时钟，在物理层定义了帧结构（也适用于微波和卫星传输体制），规定标准激光源波长为 1310 nm 和 1550 nm。
  - **SONET（美国标准）**：基本速率 `OC-1 / STS-1 = 51.84 Mbit/s`。
  - **SDH（ITU-T 国际标准）**：基本速率 `STM-1 = 155.52 Mbit/s`（对应 `OC-3 / STS-3`），对应关系为 **`OC-3n / STS-3n = STM-n`**（`OC-12 / STM-4 = 622 Mbit/s`，`OC-48 / STM-16 = 2.5 Gbit/s`，`OC-192 / STM-64 = 10 Gbit/s`，`OC-768 / STM-256 = 40 Gbit/s`）。

### 2.6 宽带接入技术

FCC 定义宽带标准为下行速率达到 25 Mbit/s、上行速率达到 3 Mbit/s。
- **ADSL（非对称数字用户线，G.992.1 / G.dmt）**：利用现有模拟电话铜线（不需重新布线），下行速率远高于上行速率（不适合企业使用，且不能保证固定数据率）。采用离散多音调 **DMT** 调制（基于 FDM，0–4 kHz 留给传统电话 POTS，约 40–138 kHz 为上行，约 138–1100 kHz 为下行）。三大组成：数字用户线接入复用器 **DSLAM**、用户线、用户家中的分离器与接入端接单元 **ATU**（ATU-C 在端局，ATU-R 在用户侧）。第二代 ADSL2/ADSL2+ 引入无缝速率自适应（SRA）、改进调制效率及线路故障定位；衍生技术包括 SDSL、HDSL、VDSL；超高速 **Giga DSL** 采用时分双工 TDD 与 OFDM 技术。
- **HFC 网（光纤同轴混合网）**：基于有线电视网 CATV 改造（主干用光纤，入户保留同轴电缆），双向传输（我国划分：上行 5–65 MHz，下行 87–1000 MHz）；用户端使用机顶盒（使模拟电视接收数字信号）和电缆调制解调器（**Cable Modem**，不需要成对使用、仅装在用户端，但须解决共享信道冲突问题）。
- **FTTx 技术**：FTTH（户）、FTTB（大楼）、FTTC（路边）、FTTZ（小区）、FTTO（办公室）、FTTD（桌面）。光配线网 **ODN** 位于光纤干线与用户之间（含端局光线路终端 **OLT**、无源 1:N 光分路器、用户侧光网络单元 **ONU**），采用 WDM 上下行波分双向传输。主流无源光网络标准：**EPON**（链路层用以太网协议，成本低）与 **GPON**（采用通用封装方法 GEM，多业务 QoS 好）。

## 第 3 章 数据链路层

数据链路层使用的信道主要有点对点信道（一对一通信）和广播信道（一对多广播通信，共享信道）。网络中的主机、路由器都必须实现物理层与数据链路层；交换机实现物理层与数据链路层；不同链路层可采用不同的数据链路层协议。

### 3.1 使用点对点信道的数据链路层

- **链路（物理链路）**：一条无源的点到点物理线路段，中间没有任何其他交换结点。
- **数据链路（逻辑链路）**：除了物理线路外，还必须有通信协议来控制数据的传输。把实现这些协议的硬件和软件加到链路上，就构成了数据链路（典型实现是网络适配器/网卡）。
- **协议数据单元**：帧（Frame）。

#### 三个基本问题
1. **封装成帧**：在一段数据的前后分别添加首部和尾部，构成一个帧；首部和尾部的一个重要作用是进行帧定界。控制字符 `SOH`（`0x01`，Start Of Header）放在帧最前面，`EOT`（`0x04`，End Of Transmission）放在帧末尾。最大传送单元 **MTU** 规定了帧数据部分的最大长度上限。
2. **透明传输**：无论发送什么样的比特组合（即使数据内部恰好出现与定界符 SOH/EOT 相同的代码），数据链路层都能原封不动地交给上层。
   - **字节填充（字符填充）**：发送端在数据中出现控制字符 SOH、EOT 或转义字符 ESC 前面插入一个转义字符 `ESC`（`0x1B`）；接收端收到后删除该 ESC。
3. **差错检测**：传输过程中可能产生比特差错（1 变成 0 或 0 变成 1）。一段时间内传输错误的比特占所传输比特总数的比率称为**误码率（BER）**。广泛采用**循环冗余检验 CRC**。
   - **CRC 计算步骤**：设待发送数据 $M$ 共 $k$ 位，双方约定除数（生成多项式）$P$ 共 $n+1$ 位（常用生成多项式：`CRC-16` $= X^{16}+X^{15}+X^2+1$、`CRC-CCITT` $= X^{16}+X^{12}+X^5+1$、以太网采用 32 位 `CRC-32` $= X^{32}+X^{26}+X^{23}+X^{22}+X^{16}+X^{12}+X^{11}+X^{10}+X^8+X^7+X^5+X^4+X^2+X+1$）：
     1. 用二进制模 2 运算将 $M$ 左移 $n$ 位（在 $M$ 后添加 $n$ 个 0），得到 $2^n M$；
     2. 用 $2^n M$ 对 $P$ 做模 2 除法（按位异或，无借位），得出 $n$ 位余数 $R$（即**帧检验序列 FCS**）；
     3. 将余数 $R$ 拼接到 $M$ 后面发送（总长度 $k+n$ 位）；接收端将收到的帧除以 $P$，若余数为 0 则判定无比特差错并接受，否则丢弃。
   - **辨析**：（1）CRC 与 FCS 并不等同（CRC 是检错方法，FCS 是冗余码）；（2）**无差错接受 $\neq$ 可靠传输**——仅用 CRC 只能保证接受的帧无比特差错，但可能存在帧丢失、帧重复、帧失序；可靠传输还需帧编号、确认与重传机制。

### 3.2 点对点协议 PPP

- **地位与特点**：目前使用最广泛的点对点数据链路层协议（RFC 1661 / STD 51）。具备简单（首要要求）、封装成帧、透明性、支持多种网络层协议、支持多种类型链路、差错检测、检测连接状态、支持 MTU、网络层地址协商、数据压缩协商等 10 项需求；**不提供**纠错、流量控制、序号及多点线路支持。
- **三个组成部分**：
  1. 一个将 IP 数据报封装到串行链路的方法；
  2. **链路控制协议 LCP**：用于建立、配置和测试数据链路连接；
  3. **网络控制协议 NCP**：每个协议对应一种网络层协议（如 IPCP）。
- **PPP 帧格式**：`F(1B, 0x7E) | A(1B, 0xFF) | C(1B, 0x03) | 协议(2B) | 信息部分(≤1500B) | FCS(2B) | F(1B, 0x7E)`。PPP 是面向字节的，所有 PPP 帧长度都是整数字节；连续两帧之间只需用一个标志字段 `0x7E`。
  - **协议字段**：`0x0021` 表示 IP 数据报，`0x8021` 表示网络控制数据（NCP），`0xC021` 表示 PPP 链路控制数据（LCP），`0xC023` 表示鉴别数据。
  - **透明传输方式**：
    - **异步传输（面向字节）**：采用**字节填充**，将信息字段中的 `0x7E` 替换为 `(0x7D, 0x5E)`，`0x7D` 替换为 `(0x7D, 0x5D)`，小于 `0x20` 的 ASCII 控制字符前加 `0x7D` 并改变编码（如 `0x03` 变为 `0x7D 0x23`）。
    - **同步传输（面向比特）**：采用**零比特填充**（5 个 1 插 1 个 0），发送端每扫描到连续 5 个 1 立即在其后填入一个 0；接收端每收到连续 5 个 1 删除其后的一个 0。
- **PPP 工作状态机**：
  `链路静止` $\xrightarrow{\text{物理层连接建立}}$ `链路建立` $\xrightarrow{\text{LCP配置协商}}$ `鉴别（PAP/CHAP）` $\xrightarrow{\text{鉴别成功或无需鉴别}}$ `网络层协议（NCP）` $\xrightarrow{\text{NCP配置协商}}$ `链路打开` $\xrightarrow{\text{链路故障或关闭请求}}$ `链路终止` $\xrightarrow{\text{LCP链路终止}}$ `链路静止`。
- **链路释放顺序**：先由 NCP 释放网络层连接并收回临时 IP，再由 LCP 释放数据链路层连接，最后释放物理层连接。

### 3.3 使用广播信道的数据链路层

#### 1. 局域网的数据链路层与适配器
- **局域网主要特点**：网络为一个单位所拥有；地理范围和站点数目均有限；具有广播功能、便于系统扩展、提高了可靠性和生存性。拓扑结构包括总线网（两端需接匹配电阻吸收总线信号）、星形网、环形网、树形网。
- **共享信道划分**：静态划分（FDM/TDM/WDM/CDM，代价高不适合局域网）与动态媒体接入控制（随机接入如以太网，受控接入如轮询）。
- **局域网两个子层**：逻辑链路控制 **LLC 子层**（与传输媒体无关）与媒体接入控制 **MAC 子层**（与传输媒体及拓扑结构有关；因以太网占绝对优势，现通常略去 LLC 子层）。
- **网络适配器（网卡）功能**：（1）进行数据的串行/并行转换；（2）对数据进行缓存；（3）在计算机操作系统中安装设备驱动程序；（4）实现以太网协议（包括封装/解封、CSMA/CD、MAC 地址过滤）。

#### 2. 以太网的两个标准与 CSMA/CD 协议
- **两大标准**：**DIX Ethernet V2** 与 **IEEE 802.3**（硬件实现可在同一局域网上互操作）。
- **以太网的两项重要措施**：（1）采用无连接的工作方式（不编号、不要求确认，尽最大努力交付）；（2）发送数据使用曼彻斯特编码（具有自同步能力，但所占频带宽度比原始基带信号增加一倍）。
- **CSMA/CD（载波监听多点接入 / 碰撞检测）要点**：
  - **多点接入**：总线型网络，多台计算机连接在一根总线上；
  - **载波监听**：“先听后发”且“边发送边监听”信道；
  - **碰撞检测**：检测总线上信号电压摆动值是否超过门限；一旦检测到碰撞，立即停止发送，接着发送 **32 或 48 bit 人为干扰信号**（强化碰撞），使所有用户都知道发生了碰撞。
  - **帧间最小间隔**：规定为 **$9.6\ \mu\text{s}$**（相当于 10 Mbit/s 以太网中 96 比特的发送时间），使接收方缓存得以清理并为下一帧做好准备。
- **争用期（碰撞窗口）**：以太网端到端往返传播时延 $2\tau$。对于 10 Mbit/s 传统以太网：
  - **争用期 $2\tau = 51.2\ \mu\text{s}$**（单程最大时延 $\tau = 25.6\ \mu\text{s}$，对应最大端到端距离约 5 km）。
  - **最短有效帧长**：$51.2\ \mu\text{s}\times 10\text{ Mbit/s} = 512\text{ bit} = 64\text{ B}$。凡长度小于 64 字节的帧均视为冲突导致的无效帧，予以丢弃。
- **截断二进制指数退避算法（动态退避）**：
  - 基本退避时间为争用期 $2\tau$；
  - 令重传次数为 $c$，参数 $k = \min[c, 10]$；
  - 从整数集合 $\{0, 1, \dots, 2^k - 1\}$ 中随机取出一个数 $r$，重传推迟时间为 $r\times 2\tau$；
  - 当重传达到 **16 次**仍不能成功时，丢弃该帧并向高层报告。

#### 3. 集线器与以太网信道利用率
- **10BASE-T 星形以太网（802.3i）**：使用两对双绞线连接**集线器（Hub）**，网段最大长度 100 m。集线器工作在物理层，相当于多接口转发器（采用专用芯片进行自适应串音回波抵消）；使用集线器的以太网在物理上是星形，逻辑上仍然是总线网，所有接口处于同一个碰撞域，工作在半双工方式。
- **以太网信道利用率**：设单程端到端传播时延为 $\tau$，帧发送时间为 $T_0 = L/C$，定义参数 $a = \frac{\tau}{T_0}$。要提高利用率应使 $a$ 尽可能小（帧长不能太短、链路不能太长）。理想情况下极限信道利用率为：
  $$S_{\max} = \frac{T_0}{T_0 + \tau} = \frac{1}{1 + a}$$

#### 4. 以太网的 MAC 层与帧格式
- **48 位 MAC 地址（6 字节硬件地址，EUI-48）**：固化在网卡 ROM 中，实为某个接口的标识符。
  - 前 3 字节（高 24 位）为组织唯一标识符 **OUI**（由 IEEE RA 分配给厂家），后 3 字节为厂家指派的扩展标识符。
  - 第 1 字节最低位为 **I/G 位**：0 表示单站地址，1 表示组地址（多播）；全 1（`FF-FF-FF-FF-FF-FF`）为广播地址（只能作目的地址）。
  - 第 1 字节次低位为 **G/L 位**：0 表示全球管理（IEEE 分配），1 表示本地管理。
  - 网卡接收过滤：仅接收单播帧、广播帧和本站加入的多播帧（混杂模式下接收听到的一切帧）。
- **以太网 V2 的 MAC 帧格式（有效总长 64–1518 字节）**：
  `目的地址(6B) | 源地址(6B) | 类型(2B) | MAC客户数据(46–1500B) | FCS(4B)`
  - 物理层发送前在帧前插入 **8 字节**（7 字节前同步码 `1010...10` + 1 字节帧开始定界符 `10101011`），传输媒体上实际传送比 MAC 帧多 8 字节。
  - 数据字段最小 46 字节来自 $64 - 18 = 46$，不足 46 字节时在数据字段后加整数字节填充。
  - **IEEE 802.3 与 V2 区别**：802.3 的第 3 个字段为“长度/类型”（值 $< \text{0x0600}$ 即 1536 时表示长度，数据字段必须装入 LLC 帧；值 $> \text{0x0600}$ 时表示类型，即 V2 格式，如 `0x0800` 为 IPv4、`0x0806` 为 ARP）。
  - **无效 MAC 帧判定（满足任一即丢弃，以太网不负责重传）**：（1）帧长不是整数个字节；（2）用 FCS 查出有差错；（3）数据字段长度不在 46–1500 字节之间；（4）802.3 帧中数据长度与“长度”字段值不一致；（5）有效帧总长不在 64–1518 字节范围内。

### 3.4 扩展的以太网

- **物理层扩展**：使用光纤（加一对光纤调制解调器）或主干集线器互连多个碰撞域，合并为一个更大的碰撞域（缺点：碰撞概率增大，总吞吐量未提高，且不能互连不同速率的以太网）。
- **链路层扩展（以太网交换机）**：实质上是多接口网桥，工作在数据链路层。
  - **特点**：每个接口直接连接一台主机或另一台交换机，一般工作在全双工方式；**每个接口是一个独立的碰撞域**（隔离碰撞域，但仍属于同一个广播域）；支持同时连通多对接口并行传输（集线器 $N$ 用户共享带宽 $B$，每人 $B/N$；交换机每个端口独享带宽 $B$，总容量达 $B\times N$）；内部帧交换表使用内容可寻址存储器（**CAM**）并用专用硬件芯片转发。
  - **交换方式**：**存储转发**（先完整接收并校验 FCS，无差错再查表转发）与**直通交换（Cut-Through）**（只检查目的 MAC 地址即立即转发，时延小但不检错）。
  - **自学习与转发流程**：交换机维护帧交换表（`MAC 地址 - 接口 - 有效时间`，设老化时间以应对更换主机或网卡）。收到一帧后：
    1. **登记（自学习）**：将帧的源 MAC 地址和进入接口写入交换表（若已存在则刷新老化时间）；
    2. **查找（转发）**：查目的 MAC 地址——若找到且对应接口 $\neq$ 进入接口，则从该接口精确转发；若对应接口 $=$ 进入接口，则丢弃（过滤）；若未找到或目的地址为广播/多播地址，则向除进入接口外的所有接口泛洪（广播）。
  - **生成树协议（STP）**：当交换机之间存在冗余物理环路时，广播帧会在环路中无限循环引发广播风暴。STP 不改变实际物理拓扑，但在逻辑上阻塞某些冗余链路，构造出无环路的树状转发结构。
- **虚拟局域网（VLAN）**：
  - **定义**：由一些局域网网段构成的与物理位置无关的逻辑组（只是局域网提供的一种服务，不是新型局域网），**每个 VLAN 是一个独立的广播域**。优点：改善性能、简化管理、降低成本、提高安全性。
  - **5 种划分方法**：基于交换机端口（第 1 层，最简单常用，不支持移动）、基于 MAC 地址（第 2 层，支持移动但管理繁琐）、基于协议类型（第 2 层）、基于 IP 子网地址（第 3 层，依据帧类型字段与 IP 源地址）、基于高层应用或服务。
  - **IEEE 802.1Q 帧格式**：在标准以太网 V2 帧的“源地址”和“类型”字段之间插入 **4 字节 VLAN 标记**（2 字节标签协议标识符 `0x8100` + 2 字节标签控制信息 TCI，含 3 位优先级 PRI、1 位 CFI 和 **12 位 VLAN 标识符 VID**，有效 VID 为 `1–4094`），数据字段对应变为 42–1500 字节，最大帧长从 1518 增至 **1522 字节**。

### 3.5 高速以太网

- **100BASE-T（快速以太网，IEEE 802.3u）**：速率 100 Mbit/s，星形拓扑，全双工时不使用 CSMA/CD；半双工时争用期缩为 **$5.12\ \mu\text{s}$**，帧间最小间隔缩为 **$0.96\ \mu\text{s}$**（最短帧长仍为 64 B，最大网段长度 100 m）。三种物理层标准：`100BASE-TX`（2 对 5 类 UTP，100 m）、`100BASE-FX`（2 根光纤，2000 m）、`100BASE-T4`（4 对 3 类 UTP，100 m）。
- **吉比特以太网（1GE）**：采用现有以太网与 ANSI 光纤通道（FC）两种技术，允许全双工和半双工工作。为在半双工下同时保持 64 B 最短帧长和 100 m 网段长度，引入两项技术：
  - **载波延伸（Carrier Extension）**：将争用期增至 **512 字节**，若 MAC 帧不足 512 字节则在后面填充特殊字符；
  - **分组突发（Packet Bursting）**：连续发送多个短帧时，仅第 1 个短帧采用载波延伸，后续短帧紧接发送（突发计时器上限 **1500 字节**）。
  - 物理层标准：`1000BASE-SX`（多模光纤，550 m）、`1000BASE-LX`（单/多模光纤，5000 m）、`1000BASE-CX`（2 对 STP，25 m）、`1000BASE-T`（4 对 5 类 UTP，100 m）。
- **10GE / 40GE / 100GE 以太网**：仅工作在全双工方式（不再使用 CSMA/CD），保留 64–1518 B 帧格式，工作范围扩展至城域网和广域网。10GE 标准：`10GBASE-SR`（多模 0.85 μm，300 m）、`10GBASE-LR`（单模 1.3 μm，10 km）、`10GBASE-ER`（单模 1.5 μm，40 km）、`10GBASE-CX4`（4 对双芯同轴，15 m）、`10GBASE-T`（4 对 6A 类 UTP，100 m）。
- **以太网宽带接入与 PPPoE**：IEEE 802.3 EFM 工作组提出以太网宽带接入，但纯以太网不支持用户身份鉴别；**PPPoE（PPP over Ethernet）**将 PPP 帧封装在以太网 MAC 帧中传输，兼顾以太网低成本高速接入与 PPP 的用户鉴别计费，广泛用于 ADSL 与 FTTx 宽带接入。

## 第 4 章 网络层

### 4.1 网络层的几个重要概念

#### 1. 网络层提供的两种服务对比

| 对比项目 | 虚电路服务（VC，面向连接） | 数据报服务（Datagram，无连接，互联网采用） |
| :--- | :--- | :--- |
| **设计思路** | 可靠通信应当由网络来保证 | 可靠通信应当由用户主机（端系统）来保证 |
| **连接建立** | 必须先建立连接（虚电路） | 不需要建立连接 |
| **终点地址** | 仅在连接建立阶段使用，每个分组使用短的虚电路号 | 每个分组都必须带有完整的源地址和目的地址 |
| **分组转发路径** | 属于同一条虚电路的所有分组均按同一路径转发 | 每个分组独立选择路由，不同分组路径可能不同 |
| **路由器故障影响** | 经过故障结点的所有虚电路均不能工作 | 出故障的结点丢失分组，其余分组可绕行选路 |
| **分组顺序与差错** | 总是按发送顺序到达；可由网络保证可靠 | 不一定按序到达；尽最大努力交付（不保证不丢失） |
| **端到端差错与流控** | 可由网络负责，也可由用户主机负责 | 由用户主机负责 |

#### 2. 网络层的两个层面
- **数据层面（转发层面）**：路由器根据本机转发表将收到的分组从合适接口转发出去（硬件实现，纳秒级，局部动作）。
- **控制层面**：路由器之间运行路由选择协议交换路由信息，通过路由选择算法计算并生成路由表（软件实现，毫秒/秒级，全局动作）。

### 4.2 网际协议 IPv4

与 IPv4 配套的 3 个重要协议：**地址解析协议 ARP**、**网际控制报文协议 ICMP**、**网际组管理协议 IGMP**。

#### 1. 虚拟互连网络与中间设备
- **各层中间设备**：物理层——**转发器（Repeater）、集线器（Hub）**；数据链路层——**网桥（Bridge）、以太网交换机（Switch）**；网络层——**路由器（Router）**（只有使用路由器互连多个网络才称为网络互连；桥路器 brouter 为网桥与路由器混合）；网络层以上——**网关（Gateway）**。
- **IP 网的意义**：使用 IP 协议屏蔽底层各种异构网络的物理细节，使互联网看起来像一个统一的虚拟网络。

#### 2. 分类的 IP 地址与特殊 IP 地址
32 位 IPv4 地址（由 ICANN 统一管理分配）采用点分十进制表示，早期分为 A、B、C、D、E 五类（两级结构 `<网络号>, <主机号>`）：

| 类别 | 最高位前缀 | 网络号位数 | 可指派网络数 | 每个网络最大主机数 | 首字节范围 |
| :--- | :---: | :---: | :--- | :--- | :---: |
| **A 类** | `0` | 8 位（固定 1 位） | $2^7 - 2 = 126$（`1–126`） | $2^{24} - 2 = 16,777,214$ | 1–126 |
| **B 类** | `10` | 16 位（固定 2 位） | $2^{14} - 1 = 16,383$（`128.1–191.255`） | $2^{16} - 2 = 65,534$ | 128–191 |
| **C 类** | `110` | 24 位（固定 3 位） | $2^{21} - 1 = 2,097,151$（`192.0.1–223.255.255`） | $2^8 - 2 = 254$ | 192–223 |
| **D 类** | `1110` | 多播地址 | — | — | 224–239 |
| **E 类** | `1111` | 保留今后使用 | — | — | 240–255 |

- **特殊 IP 地址汇总**：

| 网络号 | 主机号 | 可作源地址 | 可作目的地址 | 含义 |
| :---: | :---: | :---: | :---: | :--- |
| `0` | `0` | 可以 | 不可 | 在本网络上的本主机（如 DHCP Discover） |
| `0` | `X` | 可以 | 不可 | 在本网络上主机号为 X 的主机 |
| `全 1` | `全 1` | 不可 | 可以 | 本网络上的受限广播地址（`255.255.255.255`，路由器不转发） |
| `Y` | `全 1` | 不可 | 可以 | 对网络号为 Y 的网络上所有主机的直接广播地址 |
| `127` | 非全 0/全 1 | 可以 | 可以 | 本地软件环回测试地址（如 `127.0.0.1`，分组不离开本机） |

#### 3. 无分类编址 CIDR 与路由聚合
- **斜线记法**：`IP地址/网络前缀位数`（如 `128.14.35.7/20`），消除了 A/B/C 类与子网划分界限。注意区分：`128.14.35.7/20` 指明某地址及其前缀；`128.14.32.0/20` 指明地址块（全 0 主机号）；不带前缀的 `128.14.32.0` 不能指明网络地址。
- **地址块与地址掩码**：网络前缀相同的连续 IP 组成一个 CIDR 地址块（总地址数为 $2^{32-n}$）。网络地址 $= \text{IP}\land\text{地址掩码}$；常规可用主机数为 $2^{32-n}-2$（扣除全 0 网络地址与全 1 广播地址）。
- **构造超网（路由聚合）**：将多个连续的小 CIDR 地址块聚合成一个前缀更短的大地址块，减少路由表项数量。例：16 个 C 类网 `192.24.0`–`192.24.15` 聚合为 `192.24.0.0/20`。
- **三个特殊 CIDR 地址块**：
  - `/32`（`255.255.255.255`）：主机路由（指明单个特定 IP）；
  - `/31`（`255.255.255.254`）：点对点链路（仅含 2 个地址，主机号 0 和 1 均可用，不减 2）；
  - `/0`（`0.0.0.0/0`）：默认路由。
- **多归属主机与路由器接口**：连接多个网络的主机具有多个 IP 地址（多归属主机）；路由器至少连接两个不同网络，每个接口拥有不同网络号的 IP 地址。

#### 4. IP 地址与 MAC 地址的逐跳变化
- **变化规律**：不经过 NAT 时，源/目的 **IP 地址端到端保持不变**；每经过一台路由器转发，源/目的 **MAC 地址均发生改变**（仅在本段物理链路有效）。
- **同时使用 IP 和 MAC 两种地址的原因**：底层存在多种异构物理网络，硬件地址格式互不兼容；在网络层统一使用抽象的 32 位 IP 地址可屏蔽底层差异实现虚拟互连，在每段物理链路上再借助 ARP 解析实际 MAC 地址完成帧交付。

#### 5. 地址解析协议 ARP
- **作用**：在同一局域网内，由已知的 32 位 IP 地址解析出对应的 48 位 MAC 地址。
- **工作过程**：主机先查本地 **ARP 高速缓存**（`<IP地址, MAC地址, 生存时间 Age, 类型>`，动态老化以适应更换网卡）；若未命中，则在本局域网**广播 ARP 请求分组**（目标 MAC 填 0，且自带发送方 IP-MAC 映射供目标顺便写入缓存），目标主机收到后**单播返回 ARP 响应分组**（路由器不转发 ARP 广播请求）。
- **使用 ARP 的 4 种典型情况**：
  1. 发送方是主机，要把 IP 数据报发送到本网络的另一台主机 $\to$ 用 ARP 找目的主机的 MAC 地址；
  2. 发送方是主机，要把 IP 数据报发送到另一个网络的主机 $\to$ 用 ARP 找本网络上默认路由器接口的 MAC 地址；
  3. 发送方是路由器，要把 IP 数据报转发到本网络的一台主机 $\to$ 用 ARP 找目的主机的 MAC 地址；
  4. 发送方是路由器，要把 IP 数据报转发到另一个网络的主机 $\to$ 用 ARP 找下一跳路由器接口的 MAC 地址。

#### 6. IPv4 数据报的首部格式与分片
IPv4 首部固定部分为 20 字节，可变部分（选项+填充）0–40 字节，总首部长度 20–60 字节。

- **核心字段与单位**：
  - **版本（4 位）**：4（IPv4）。
  - **首部长度（IHL，4 位）**：以 **4 字节**为单位（最小值 5 表示 20 B，最大值 15 表示 60 B）。
  - **区分服务（8 位）**：用于 QoS 优先级区分。
  - **总长度（16 位）**：首部与数据之和，以 **1 字节**为单位，最大值 65535 B。
  - **标识（16 位）**：同一数据报分片后的所有分片具有相同的标识值。
  - **标志（3 位）**：最低位 **MF**（1 表示后面还有分片，0 表示最后一个分片）；中间位 **DF**（1 表示不允许分片，0 表示允许分片）。
  - **片偏移（13 位）**：分片后某片在原分组中的相对位置，以 **8 字节**为单位（除最后一个分片外，前面每片的数据载荷长度必须是 8 字节的整数倍）。
  - **生存时间 TTL（8 位）**：跳数上限，每经过一个路由器减 1；减为 0 时丢弃数据报并向源站发送 ICMP 时间超过差错报告。
  - **协议（8 位）**：`ICMP=1`、`IGMP=2`、`IP=4`、`TCP=6`、`EGP=8`、`IGP=9`、`UDP=17`、`IPv6=41`、`ESP=50`、`AH=51`、`ICMPv6=58`、`OSPF=89`。
  - **首部检验和（16 位）**：**只检验首部，不检验数据部分**（16 位二进制反码求和；因 TTL 每跳减 1，每经过一个路由器必须重新计算）。
  - **源地址、目的地址**：各占 32 位（4 字节）。

### 4.3 IP 层转发分组的流程

- **基于终点的转发与最长前缀匹配**：路由器转发表存放 `(目的网络前缀, 下一跳)`。查找转发表时若同时匹配多个表项，选择**网络前缀最长（地址块最小、路由最具体）**的一条。
- **两种特殊路由**：**特定主机路由（`/32`）**（优先级最高）与**默认路由（`0.0.0.0/0`）**（优先级最低）。
- **路由器分组转发算法**：
  1. 提取分组目的 IP 地址 $D$；
  2. 若存在 $D$ 的特定主机路由则按之转发；否则检查各直连网络，若 $D$ 与某直连网络掩码按位与等于该网络前缀则直接交付；
  3. 否则查转发表（按最长前缀匹配）：若匹配则转发给对应下一跳路由器（间接交付）；
  4. 否则若存在默认路由则转发给默认路由器；否则丢弃并报告转发分组出错（发送 ICMP 终点不可达）。
- **二叉线索（Binary Trie）**：最大深度 32 层，利用**唯一前缀**构造树结构加速查表；查找到叶节点后，必须将目的 IP 与该叶节点保存的子网掩码做按位 AND 运算，验证是否真正与叶节点网络前缀匹配。

### 4.4 网际控制报文协议 ICMP

ICMP 是 **IP 层协议**（封装在 IP 数据报中，协议号 1），用于报告差错和提供异常情况报告。
- **ICMP 差错报告报文（4 种）**：
  1. **终点不可达（Type 3）**（网络/主机/端口不可达等）；
  2. **时间超过（Type 11）**（TTL 减为 0 或分片重组超时）；
  3. **参数问题（Type 12）**（IP 首部字段值不正确）；
  4. **改变路由/重定向 Redirect（Type 5）**（通知主机存在更优下一跳）。
  - 数据部分包含出错 IP 数据报的首部及其数据部分的**前 8 个字节**（以便提取运输层端口号定位进程）。
- **不应发送 ICMP 差错报告报文的 4 种情况**：（1）对 ICMP 差错报告报文本身；（2）对第一个分片的后续分片；（3）对具有多播地址的数据报；（4）对具有特殊地址（如 `127.0.0.0` 或 `0.0.0.0`）的数据报。
- **ICMP 询问报文（2 种）**：**回送请求/回答（Type 8 / 0）**、**时间戳请求/回答（Type 13 / 14）**。
- **典型应用**：
  - **PING**：应用层直接使用网络层 ICMP（不经 TCP/UDP），利用回送请求与回答测试两台主机连通性。
  - **Traceroute / tracert**：从 `TTL=1` 开始逐次递增发送 UDP（或 ICMP）探测报文，利用沿途路由器返回的 ICMP 时间超过报文和终点返回的 ICMP 终点不可达报文，跟踪路径与每跳时延。

### 4.5 IPv6

- **基本首部（固定 40 字节，8 个字段，8 字节对齐）**：版本（4b，值 6）、通信量类（8b）、**流标号（20b）**、有效载荷长度（16b，最大 64 KB）、下一个首部（8b）、跳数限制（8b）、源地址与目的地址（各 128b）。
  - **相比 IPv4 取消的字段**：首部长度、服务类型、总长度、分片字段（**中间路由器不再分片**，由源主机通过分片扩展首部处理）、协议字段、检验和字段、选项字段。支持**即插即用自动配置（可不使用 DHCP）**与资源预分配。
- **扩展首部**：逐跳选项、路由选择、分片、鉴别、封装安全有效载荷、目的站选项，链式连接。
- **IPv6 地址（128 位）**：
  - 冒号十六进制记法（每 16 位一组，共 8 组）；**零压缩 `::` 在一个地址中只能使用一次**；支持点分十进制后缀（如 `::128.10.2.1`）与 CIDR 斜线记法（取消子网掩码）。
  - 三种基本类型：**单播、多播、任播（Anycast，发往一组接口中距离最近的一个；取消了广播）**。
  - 特殊与分类地址：未指明地址 `::/128`、环回地址 `::1/128`、多播地址 `FF00::/8`、本地链路单播地址 `FE80::/10`、全球单播地址（其余前缀）。
- **IPv4 向 IPv6 过渡技术**：
  - **双协议栈**：同时运行 IPv4 和 IPv6 协议栈（IPv6 与 IPv4 转换时会丢失流标号等 IPv6 特有字段）。
  - **隧道技术**：将整个 IPv6 数据报封装在 IPv4 数据报的数据部分（协议号 41），穿过 IPv4 网络后解封装，可完整保留流标号。
- **ICMPv6**：整合了原 IPv4 中的 ICMP、ARP（邻居发现协议 NDP）和 IGMP 的功能。

### 4.6 互联网的路由选择协议

#### 1. 自治系统与三大路由选择协议对比
整个互联网划分为许多自治系统（AS），内部使用内部网关协议 **IGP（RIP、OSPF）**，AS 之间使用外部网关协议 **EGP（BGP-4）**。

| 对比维度 | RIP（IGP） | OSPF（IGP，OSPFv2） | BGP-4（EGP） |
| :--- | :--- | :--- | :--- |
| **算法核心** | 距离向量（Bellman-Ford） | 链路状态（Dijkstra SPF） | 路径向量（Path Vector） |
| **路径度量** | 跳数（直连为 1，最大 15，16 表示不可达） | 代价 Cost（带宽、时延等，最高 16 位） | 策略优先：`LOCAL-PREF` 最高 $\to$ `AS-PATH` 最短 $\to$ 热土豆路由 |
| **交换方式与周期** | 仅与相邻路由器每 **30 s** 周期性交换完整路由表（**180 s** 无更新置 16） | 向本区域所有路由器通过**洪泛法**发送相邻链路状态（变化触发 + **30 min** 刷新） | 相邻边界路由器间建立 eBGP / iBGP 会话（**iBGP 禁止再通告给 iBGP**） |
| **协议封装与首部** | **UDP（端口 520）**（RIP2 最多 25 项，最大 **504 B**） | **直接封装在 IP 数据报中（协议号 89）**，首部固定 **24 B** | **TCP（端口 179）**，通用首部 19 B |
| **分组 / 报文种类** | 请求、响应 | 5 种：Hello（每 **10 s**，**40 s** 判死）、DD、LSR、LSU、LSAck | 4 种：OPEN、UPDATE、KEEPALIVE、NOTIFICATION |
| **主要特点** | 实现简单、开销小，不支持负载均衡；存在**坏消息传播得慢**（慢收敛）问题 | 收敛快、无环路；支持区域划分（骨干区 `0.0.0.0`、ABR、BR、ASBR）、多路径负载均衡与指定路由器 DR | 利用 `AS-PATH` 防环，寻找较好且不兜圈子的路由；AS 分末梢、多归属、转接与对等 AS |

- **RIP 距离向量更新规则**：收到邻居 $X$ 发来的表项 `(N, d)` 后，先将下一跳改为 $X$、距离改为 $d+1$：
  1. 若本表无 $N$，直接插入；
  2. 若本表有 $N$ 且下一跳就是 $X$，无论新距离大小**强制更新**；
  3. 若本表有 $N$ 但下一跳不是 $X$，仅当新距离严格小于原距离时更新。
- **RIP 坏消息传播得慢**：当某直连网络故障（距离置 16）前，该路由器收到邻居发来的旧可达路由（如距离 2），会误以为可经邻居到达并将距离改为 3，此后两台路由器反复递增交换直至双方都达到 16 才收敛。

#### 2. 路由器的构成与交换结构
路由器由**路由选择部分（控制层面）**和**分组转发部分（输入端口、交换结构、输出端口）**组成。输入/输出端口均设队列，分组到达速率过快导致队列溢出时丢包。三种交换结构：
1. **通过存储器**：CPU 中断控制复制分组，受限于存储器带宽（若带宽为每秒 $M$ 个分组，交换速率一定小于 $M/2$）；
2. **通过总线**：输入端口经共享总线直接送往输出端口，一次仅传一个分组；
3. **通过纵横交换结构（互连网络，无阻塞）**：$2N$ 条交叉总线可同时并行连通多个互不冲突的输入/输出端口，交换速率最高。

### 4.7 IP 多播

- **多播地址**：使用 D 类 IP 地址（`224.0.0.0–239.255.255.255`），只能作目的地址。多播数据报不产生 ICMP 差错报文（PING 多播地址无响应）。
- **硬件多播地址映射**：以太网多播地址范围 `01-00-5E-00-00-00` 至 `01-00-5E-7F-FF-FF`（前 25 位固定为 `01-00-5E` 加 1 位 0），将 D 类 IP 地址的**低 23 位**直接映射到以太网多播地址低 23 位。因有 $28 - 23 = 5$ 位未参与映射，存在 **$2^5 = 32$ 个 D 类 IP 地址映射到同一硬件多播地址**的可能，需在 IP 层进一步过滤。
- **IGMP（网际组管理协议，协议号 2）**：让本地多播路由器知道本局域网是否有主机加入/退出某个多播组（不知道成员数与位置）。两阶段工作：主机发送成员报告（Report）加入组；路由器周期性（默认 **125 s**）发送成员询问（Query），组内主机采用分散延迟响应（默认最大 10 s），一台响应即抑制同组其他主机重复发送。
- **多播路由选择**：目标是以源为根构建无环路多播转发树，三种方法：（1）**洪泛与剪除**（RPB 逆向路径广播查单播路由表，遇等长最短路径选 IP 最小者，加剪枝/嫁接）；（2）**隧道技术**；（3）**基于核心的发现技术**（每组 1 棵共享转发树）。常用协议：DVMRP、CBT、MOSPF、**PIM-SM（唯一成为互联网标准）**、PIM-DM。

### 4.8 虚拟专用网 VPN 和网络地址转换 NAT

- **VPN 与 RFC 1918 专用地址**：专用地址仅在机构内部有效，互联网路由器不转发目的地址为专用地址的数据报：
  - `10.0.0.0/8`（1 个 A 类网）；
  - `172.16.0.0/12`（16 个连续 B 类网，`172.16.0.0–172.31.255.255`）；
  - `192.168.0.0/16`（256 个连续 C 类网，`192.168.0.0–192.168.255.255`）。
  - VPN 利用公用互联网经加密隧道连接不同地点的专用网，分为内联网（Intranet）、外联网（Extranet）和远程接入 VPN。
- **NAT 与 NAPT**：
  - **基本 NAT**：将内部专用 IP 与有限全球 IP 一对一映射（离开专用网替换**源 IP**，进入专用网替换**目的 IP**）；有 $n$ 个全球 IP 最多同时 $n$ 台主机上网。
  - **NAPT（网络地址与端口转换）**：同时转换 **IP 地址与运输层端口号**，使多台内网主机共用同一个全球 IP 上网。通信必须由专用网内部主机发起，内网主机不能直接充当外部访问的服务器（除非配置端口映射）。

### 4.9 多协议标签交换 MPLS 与段路由 SR

- **MPLS 特点**：工作在第二层与第三层之间（“2.5 层”）。在 MPLS 域入口对分组按**转发等价类（FEC）**分类（显式路由选择）并打上固定 **4 字节标签首部**（20 位标签值 + 3 位试验 Exp + 1 位栈底 S + 8 位 TTL）；域内各标签交换路由器 **LSR** 沿着由标签分配协议 **LDP** 建立的标签交换路径 **LSP** 进行高速**标签对换**转发（标签仅在相邻两 LSR 间有效，无需逐跳最长前缀匹配）；出口去除标签。
- **段路由（Segment Routing, SR）**：针对 LDP 复杂且资源预留协议 RSVP 不支持等价多路径（ECMP）的问题，由 SDN 控制器集中计算并下发有序“段（标签）列表”封装在分组首部中。向 IPv6 演进形成 **SRv6**（直接利用 IPv6 地址字段作为 Locator）。

### 4.10 软件定义网络 SDN

- **基本概念**：将控制层面从各路由器中抽离并集中到逻辑统一的 **SDN 控制器（网络操作系统）**，数据层面交换机只执行转发。注意：**SDN $\neq$ OpenFlow**（SDN 未规定必须使用 OpenFlow）。
- **OpenFlow 广义转发（匹配 + 动作）**：流表由三部分组成：
  1. **首部匹配字段（12 个，跨三层）**：入端口 + 链路层（源/目的 MAC、类型、VLAN ID、优先级）+ 网络层（源/目的 IP、协议、服务类型）+ 运输层（TCP/UDP 源/目的端口）；不匹配则丢弃或送控制器处理；
  2. **计数器**：已匹配分组数量、距上次更新时间；
  3. **动作**：转发到指定端口、丢弃、多端口复制转发、重写第二/三/四层首部字段。
- **SDN 体系结构与控制器三层**：数据层面（SDN 交换机）经**南向接口（如 OpenFlow）**连接控制器**通信层**；控制器核心为**状态管理层**（维护全网链路/主机/交换机状态与流表）；向上经**北向接口（API）**连接网络控制应用程序（路由、接入控制、负载均衡）。

## 第 5 章 运输层

### 5.1 运输层协议概述

- **地位与作用**：运输层处于面向通信部分的最高层、用户功能的最低层。**网络层为主机之间提供逻辑通信，运输层为应用进程之间提供端到端的逻辑通信**；当应用程序使用 TCP 与 IP 时，在运输层是面向连接的，在网络层是无连接的。
- **复用与分用**：复用指发送方不同应用进程共享同一个运输层协议传送数据；分用指接收方运输层剥去首部后，根据端口号将数据准确交付给对应的应用进程。
- **端口号（16 位，0–65535）**：对 TCP/IP 体系的应用进程进行统一标志，使不同操作系统的进程可相互通信。分为三类：
  - **熟知端口号（0–1023）**：标志常规服务进程，如 `FTP（21 控制 / 20 数据）`、`SSH（22）`、`TELNET（23）`、`SMTP（25）`、`DNS（53）`、`DHCP（67 服 / 68 客）`、`TFTP（69）`、`HTTP（80）`、`POP3（110）`、`IMAP（143）`、`SNMP（161）`、`BGP（179）`、`HTTPS（443）`、`RIP（520）`。
  - **登记端口号（1024–49151）**：供没有熟知端口号的非常规服务进程使用（须在 IANA 登记）。
  - **短暂/客户端端口号（49152–65535）**：供客户进程运行时动态临时选用。

### 5.2 用户数据报协议 UDP

- **主要特点**：无连接、尽最大努力交付（不可靠，收到有差错的 UDP 数据报直接丢弃）、**面向报文**（对应用层交下来的报文既不合并也不拆分，保留报文边界）、无拥塞控制（适合 VoIP、实时音视频等对时延抖动敏感且能容忍少量丢包的应用）、支持一对一/一对多/多对多通信、首部开销小（固定 8 字节，故无需首部长度字段）。
- **UDP 首部（8 字节）**：`源端口（2B）| 目的端口（2B）| 长度（2B，首部+数据总字节数，最小 8）| 检验和（2B）`。
- **UDP 检验和与伪首部**：计算检验和时在 UDP 用户数据报前临时添加 **12 字节伪首部**（源 IP 4B + 目的 IP 4B + 全 0 1B + 协议号 17 1B + UDP 长度 2B），伪首部既不向下传送也不向上交付；对伪首部、UDP 首部与数据部分一起按 16 位二进制反码求和再取反。

### 5.3 传输控制协议 TCP 与可靠传输原理

- **主要特点**：面向连接、点对点（一对一）、提供可靠交付（无差错、不丢失、不重复、按序到达）、全双工通信、**面向字节流**（把应用层数据看作无结构的字节流，不保留报文边界，但维持字节顺序）。
- **TCP 连接与套接字**：TCP 连接的端点是**套接字（Socket）**，表示为 `IP地址 : 端口号`；一条 TCP 连接由 `{Socket1, Socket2}` 四元组唯一确定。
- **可靠传输的工作原理**：
  - **停止等待协议**：每发一个分组就停止等待对方确认；采用**超时重传**应对分组或确认丢失，使用**序号**区分新旧分组；收到重复分组须丢弃并**重发确认**（否则相当于确认丢失）。
  - **连续 ARQ 协议与滑动窗口**：发送方维持发送窗口，连续发送窗口内的多个分组；接收方采用**累积确认**，对按序到达的最后一个分组发送确认（因此个别确认丢失不一定引起重传）。
  - **窗口大小约束**：若用 $n$ 比特给分组编号（序号空间 $2^n$），当接收窗口 $W_R = 1$（仅按序接收，GBN）时，发送窗口必须满足 **$W_T \le 2^n - 1$**（否则全部 ACK 丢失重传时接收方无法区分新旧 0 号分组）；选择重传（SR）须满足 $W_T + W_R \le 2^n$。

### 5.4 TCP 报文段首部格式与可靠传输的实现

#### 1. TCP 报文段首部格式（固定 20 字节，最大 60 字节）

- **源端口、目的端口（各 2 字节）**：放在首部最前 4 字节，是因为 ICMP 差错报文仅携带 IP 首部后的前 8 字节数据，TCP 收到 ICMP 差错时可借此迅速定位出错连接。
- **序号（seq，4 字节）**：本报文段所发送数据的第一个字节的序号（超过 $2^{32}$ 可循环使用序号）。
- **确认号（ack，4 字节）**：期望收到对方下一个报文段的第一个数据字节的序号；确认号为 $N$ 表示序号 $N-1$ 及以前的所有字节都已正确收到。
- **数据偏移（4 位）**：TCP 首部长度，以 **4 字节**为单位（最小值 5 表示 20 字节，最大值 15 表示 60 字节）。
- **6 个控制位**：`URG`（紧急指针有效）、`ACK`（确认号有效，连接建立后所有报文段置 1）、`PSH`（尽快交付应用进程）、`RST`（复位连接）、`SYN`（同步序号，用于建连）、`FIN`（终止连接，数据已发完）。
- **窗口（rwnd，2 字节）**：接收窗口，用于流量控制，指明允许对方发送的数据量（字节数）。
- **检验和（2 字节）**：计算时同样临时添加 12 字节伪首部（协议号为 6）。
- **选项**：最大报文段长度 **MSS**（TCP 数据载荷最大长度，以太网常用 `1500 - 20 - 20 = 1460 B`）；窗口扩大选项；时间戳选项；**选择确认 SACK**（允许接收方通告不连续到达的字节块边界，最多指明 4 个边界块，减少重复重传）。

#### 2. 超时重传时间（RTO）的选择与 Karn 算法
- **加权平均往返时间**：
  $$\text{RTT}_S(\text{新}) = (1-\alpha)\cdot \text{RTT}_S(\text{旧}) + \alpha\cdot \text{RTT}_{\text{样本}}$$
  推荐 $\alpha = 1/8 = 0.125$；首次测量取 $\text{RTT}_S = \text{RTT}_1$。
- **RTT 偏差的加权平均值**：
  $$\text{RTT}_D(\text{新}) = (1-\beta)\cdot \text{RTT}_D(\text{旧}) + \beta\cdot |\text{RTT}_S - \text{RTT}_{\text{样本}}|$$
  推荐 $\beta = 1/4 = 0.25$；首次测量取 $\text{RTT}_D = \text{RTT}_1 / 2$。
- **超时重传时间**：$\text{RTO} = \text{RTT}_S + 4\times \text{RTT}_D$。
- **Karn 算法**：在计算平均往返时间时，**只要报文段重传了，就不采用其往返时间样本**（避免无法判断确认对应原报文还是重传报文而导致 RTO 失真）；修正算法规定报文段每重传一次就把新的 RTO 增大为原来的 2 倍，直到不再重传再按原公式计算。

### 5.5 TCP 流量控制与拥塞控制

#### 1. 流量控制与传输效率
- **流量控制（端到端）**：利用滑动窗口使发送速率与接收方接收能力匹配。当接收方通告 `rwnd = 0` 时，发送方启动**持续计时器**，到期后发送 1 字节的**零窗口探测报文段**以打破死锁。
- **提高 TCP 传输效率**：
  - **Nagle 算法**：解决发送方频繁发送极小分组的问题——先发送第一个到达的字节，将其后到达的数据缓存，待收到前一字节的确认或缓存攒满一个 MSS 时再发出。
  - **糊涂窗口综合征**：接收缓存已满且应用进程每次仅读取极少字节时，接收方等待缓存腾出至少 $\min(\text{MSS}, \text{缓存空间一半})$ 再通告非零窗口。

#### 2. 拥塞控制（全局性）
发送方窗口上限为 $\min[\text{rwnd}, \text{cwnd}]$。四大核心算法：
1. **慢开始**：初始置拥塞窗口 `cwnd = 1 MSS`；每经过一个 RTT，`cwnd` 翻倍（指数增长）。当 `cwnd ≥ ssthresh`（慢开始门限）时转入拥塞避免（若下一轮翻倍将超过门限，则下一轮直接取 `ssthresh`）。
2. **拥塞避免**：每经过一个 RTT，`cwnd` 增加 `1 MSS`（**加法增大**，线性增长）。
3. **发生网络超时（Timeout，乘法减小）**：将慢开始门限更新为 `ssthresh = max(cwnd / 2, 2)`，同时令 `cwnd = 1`，重新执行慢开始。
4. **快重传与快恢复**：
   - **快重传**：发送方一连收到 **3 个重复的 ACK** 时，立即重传对方尚未收到的报文段，不必等待超时计时器到期。
   - **快恢复**：令 `ssthresh = cwnd / 2`，同时令 `cwnd = ssthresh`，直接进入拥塞避免阶段。
- **主动队列管理（AQM）**：路由器传统的尾部丢弃策略易导致多条 TCP 连接同时降速与提速（**全局同步**）；AQM（如随机早期检测 RED）在队列满之前按概率提前丢弃分组，通知发送方降速以避免全局同步。

### 5.6 TCP 运输连接管理

#### 1. 三次握手建立连接
1. **客户 $\to$ 服务器**：`SYN=1, seq=x`（消耗 1 个序号，不能携带数据），客户进入 `SYN-SENT` 状态。
2. **服务器 $\to$ 客户**：`SYN=1, ACK=1, seq=y, ack=x+1`（消耗 1 个序号），服务器进入 `SYN-RCVD` 状态。
3. **客户 $\to$ 服务器**：`ACK=1, seq=x+1, ack=y+1`（可携带数据；不携带数据时不消耗序号），双方进入 `ESTABLISHED` 状态。
- **采用三次握手的原因**：确保双方收发能力正常并协商初始序号，同时**防止已失效的连接请求报文段突然又传送到服务器，产生错误连接与资源浪费（或死锁）**。

#### 2. 四次挥手释放连接
1. **客户 $\to$ 服务器**：`FIN=1, seq=u`，客户进入 `FIN-WAIT-1`。
2. **服务器 $\to$ 客户**：`ACK=1, seq=v, ack=u+1`，服务器进入 `CLOSE-WAIT`（**半关闭**状态，服务器仍可向客户发送剩余数据，保证不丢失数据），客户进入 `FIN-WAIT-2`。
3. **服务器 $\to$ 客户**：`FIN=1, ACK=1, seq=w, ack=u+1`，服务器进入 `LAST-ACK`。
4. **客户 $\to$ 服务器**：`ACK=1, seq=u+1, ack=w+1`，客户进入 **`TIME-WAIT`** 状态，等待 **2MSL**（最长报文段寿命）后进入 `CLOSED`；服务器收到后即进入 `CLOSED`。
- **TIME-WAIT 等待 2MSL 的原因**：
  1. 保证客户发送的最后一个 ACK 报文段能够到达服务器（若丢失，服务器重发 FIN，客户在 2MSL 内可收到并重发 ACK）；
  2. 使本连接持续时间内产生的所有报文段都从网络中消失，避免旧连接报文段干扰新连接。
- **有限状态机特殊变迁**：当通信双方同时主动打开 TCP 连接时，状态变迁为 `CLOSED → SYN-SENT → SYN-RCVD → ESTABLISHED`。

## 第 6 章 应用层

### 6.1 域名系统 DNS

- **作用**：将域名解析为 IP 地址，主要运行在 **UDP 端口 53**（主从域名服务器区域传送使用 **TCP 端口 53**）。
- **域名服务器分类**：根域名服务器、顶级域名服务器、权限域名服务器、本地域名服务器。
- **两种查询方式**：
  - **递归查询**：本地域名服务器代为向根服务器、顶级服务器等逐级查询直到获得最终结果，再返回给主机（主机向本地域名服务器通常采用递归查询）。
  - **迭代查询**：上级域名服务器返回下一级应当查询的域名服务器 IP 地址，由本地域名服务器自己继续向下一级查询。

### 6.2 文件传送协议 FTP 与远程终端

- **FTP**：基于 TCP 的双连接工作模式。
  - **控制连接（端口 21）**：传输控制命令与响应，在整个会话期间始终保持打开。
  - **数据连接（端口 20）**：传输实际文件，传输完毕立即关闭。
- **TELNET / SSH**：远程终端登录协议。TELNET（TCP 端口 23）明文传输；SSH（TCP 端口 22）加密传输。

### 6.3 万维网 WWW 与 HTTP 协议

- **URL 格式**：`<协议>://<主机>:<端口>/<路径>`。
- **HTTP 版本演进**：
  - **HTTP/1.0**：非持续连接，每个对象都需要重新建立 TCP 连接，耗费 2 RTT。
  - **HTTP/1.1**：持续连接（复用底层 TCP 连接，分为非流水线与流水线方式）。
  - **HTTP/2**：二进制分帧、多路复用、首部压缩（HPACK）。
  - **HTTP/3**：基于 UDP 的 QUIC 协议，消除 TCP 队头阻塞。
- **常用 HTTP 状态码**：`200 OK`（请求成功）；`301 Moved Permanently`（永久重定向）、`302 Found`（临时重定向）；`400 Bad Request`（语法错误）、`403 Forbidden`（拒绝访问）、`404 Not Found`（资源不存在）；`500 Internal Server Error`（服务器内部错误）、`502 Bad Gateway`（网关错误）。
- **Cookie**：保存在用户本地终端上的状态信息，用于让无状态的 HTTP 服务器识别用户会话。

### 6.4 电子邮件与动态主机配置协议 DHCP

#### 1. 电子邮件协议
- **SMTP（TCP 端口 25）**：用于用户代理向邮件服务器发送邮件，以及邮件服务器之间转发邮件（只支持 7 位 ASCII 码，多格式附件需借助 **MIME** 扩充）。
- **POP3（TCP 端口 110）与 IMAP（TCP 端口 143）**：用于用户代理从邮件服务器读取邮件；IMAP 支持在服务器端管理文件夹与部分下载。

#### 2. 动态主机配置协议 DHCP
- 基于 **UDP（服务器端口 67，客户端端口 68）**，实现 IP 地址、子网掩码、默认网关与 DNS 服务器的自动配置（跨网段需配置 **DHCP 中继代理**）。
- **四步广播交互过程**：
  1. 客户广播 `DHCP Discover`（源 IP `0.0.0.0`，目的 IP `255.255.255.255`）；
  2. 服务器广播 `DHCP Offer`（提供候选 IP 地址与租用期）；
  3. 客户广播 `DHCP Request`（选定并请求使用某个服务器提供的 IP）；
  4. 服务器广播 `DHCP ACK`（确认分配并下发网络参数）。
